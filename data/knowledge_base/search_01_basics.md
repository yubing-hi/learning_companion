# 查找（Searching）

## 一、查找的基本概念

### 1.1 定义
查找是在给定的数据集合中寻找特定元素的过程。查找成功返回元素位置或相关信息，查找失败返回特定标识。

### 1.2 基本术语
- **查找表**：由同一类型的数据元素构成的集合
- **关键字**：数据元素中某个可以标识该元素的数据项
- **主关键字**：可以唯一标识一个记录的关键字
- **次关键字**：可以标识多个记录的关键字
- **静态查找表**：只进行查找操作的查找表
- **动态查找表**：在查找过程中同时进行插入和删除操作的查找表
- **平均查找长度（ASL）**：查找过程中关键字比较次数的期望值

### 1.3 查找算法评价指标
- **时间复杂度**：主要关注关键字比较次数
- **空间复杂度**：算法所需的额外存储空间
- **平均查找长度（ASL）**：衡量查找效率的重要指标
- **适用场景**：数据规模、是否有序、是否频繁更新等

## 二、静态查找表

### 2.1 顺序查找
#### 2.1.1 算法思想
从表的一端开始，逐个比较关键字，直到找到目标元素或遍历完整个表。

#### 2.1.2 算法实现
```c
int SequentialSearch(int arr[], int n, int key) {
    for (int i = 0; i < n; i++) {
        if (arr[i] == key) {
            return i;
        }
    }
    return -1;
}
```

#### 2.1.3 性能分析
- 时间复杂度：O(n)
- 空间复杂度：O(1)
- ASL（成功）：(n+1)/2
- ASL（失败）：n
- 优点：对表结构无要求，适用于链式存储
- 缺点：效率低，不适合大规模数据

### 2.2 折半查找（二分查找）
#### 2.2.1 算法思想
在有序表中，取中间元素与目标值比较，根据比较结果在左半部分或右半部分继续查找。

#### 2.2.2 算法实现
```c
int BinarySearch(int arr[], int n, int key) {
    int low = 0, high = n - 1;
    while (low <= high) {
        int mid = (low + high) / 2;
        if (arr[mid] == key) {
            return mid;
        } else if (arr[mid] < key) {
            low = mid + 1;
        } else {
            high = mid - 1;
        }
    }
    return -1;
}
```

#### 2.2.3 性能分析
- 时间复杂度：O(log n)
- 空间复杂度：O(1)
- ASL（成功）：log₂(n+1)-1
- 要求：表必须有序且采用顺序存储
- 优点：效率高
- 缺点：要求数据有序，不适用于频繁插入删除的场景

### 2.3 分块查找（索引顺序查找）
#### 2.3.1 算法思想
将表分成若干块，块内元素可以无序，但块间有序。建立索引表，包含各块的最大关键字和起始位置。

#### 2.3.2 查找过程
1. 在索引表中查找目标关键字所在的块
2. 在该块内进行顺序查找

#### 2.3.3 性能分析
- ASL = Lb + Lw（Lb为索引表查找长度，Lw为块内查找长度）
- 最优块大小：s = √n
- 最优ASL：√n + 1
- 优点：插入删除相对容易，适合动态表
- 缺点：需要额外的索引空间

## 三、动态查找表

### 3.1 二叉排序树（BST）
#### 3.1.1 定义
二叉排序树或为空树，或具有以下性质：
- 左子树上所有结点的值均小于根结点的值
- 右子树上所有结点的值均大于根结点的值
- 左右子树也分别为二叉排序树

#### 3.1.2 查找算法
```c
BSTNode* SearchBST(BSTNode* root, int key) {
    if (root == NULL || root->data == key) {
        return root;
    }
    if (key < root->data) {
        return SearchBST(root->left, key);
    } else {
        return SearchBST(root->right, key);
    }
}
```

#### 3.1.3 插入算法
```c
bool InsertBST(BSTNode** root, int key) {
    if (*root == NULL) {
        *root = (BSTNode*)malloc(sizeof(BSTNode));
        (*root)->data = key;
        (*root)->left = (*root)->right = NULL;
        return true;
    }
    if (key == (*root)->data) {
        return false; // 已存在
    }
    if (key < (*root)->data) {
        return InsertBST(&(*root)->left, key);
    } else {
        return InsertBST(&(*root)->right, key);
    }
}
```

#### 3.1.4 性能分析
- 平均时间复杂度：O(log n)
- 最坏时间复杂度：O(n)（退化为链表）
- 空间复杂度：O(n)
- 优点：动态插入删除方便
- 缺点：可能退化为单支树

### 3.2 平衡二叉树（AVL树）
#### 3.2.1 定义
平衡二叉树是空树或满足以下条件的二叉排序树：
- 左右子树都是平衡二叉树
- 左右子树的高度差的绝对值不超过1

#### 3.2.2 平衡调整
- LL型：右旋
- RR型：左旋
- LR型：先左旋后右旋
- RL型：先右旋后左旋

#### 3.2.3 性能分析
- 查找、插入、删除时间复杂度：O(log n)
- 空间复杂度：O(n)
- 优点：保证查找效率稳定
- 缺点：维护平衡的开销较大

### 3.3 B树和B+树
#### 3.3.1 B树特点
- 多路平衡查找树
- 所有叶子结点在同一层
- 适用于外存查找

#### 3.3.2 B+树特点
- 非叶子结点仅起索引作用
- 叶子结点包含全部关键字并按顺序链接
- 适合范围查询和顺序访问

## 四、哈希表

### 4.1 哈希函数构造方法
- **直接定址法**：H(key) = a × key + b
- **数字分析法**：取关键字的某些数位
- **平方取中法**：取关键字平方后的中间几位
- **折叠法**：将关键字分割成位数相同的几部分，然后叠加
- **除留余数法**：H(key) = key MOD p（p ≤ m，m为表长）

### 4.2 处理冲突的方法
#### 4.2.1 开放定址法
- **线性探测法**：Hi = (H(key) + di) MOD m，di = 1,2,...,m-1
- **二次探测法**：di = 1², -1², 2², -2², ...
- **双重散列法**：Hi = (H(key) + di × H2(key)) MOD m

#### 4.2.2 链地址法
- 将所有哈希地址相同的记录链接在同一个单链表中
- 建立一个指针数组，每个指针指向一个链表

### 4.3 性能分析
- **装填因子 α = 表中填入的记录数 / 哈希表长度**
- 平均查找长度依赖于装填因子
- 理想情况下时间复杂度：O(1)
- 空间复杂度：O(m)

## 五、查找算法对比分析

### 5.1 时间复杂度对比
| 查找方法 | 平均时间复杂度 | 最坏时间复杂度 | 空间复杂度 |
|---------|---------------|---------------|-----------|
| 顺序查找 | O(n) | O(n) | O(1) |
| 折半查找 | O(log n) | O(log n) | O(1) |
| 二叉排序树 | O(log n) | O(n) | O(n) |
| 平衡二叉树 | O(log n) | O(log n) | O(n) |
| 哈希表 | O(1) | O(n) | O(m) |

### 5.2 适用场景对比
| 查找方法 | 数据有序性要求 | 动态性 | 存储结构 | 适用场景 |
|---------|---------------|--------|----------|----------|
| 顺序查找 | 无要求 | 支持 | 顺序/链式 | 小规模数据 |
| 折半查找 | 必须有序 | 不支持 | 顺序 | 静态有序表 |
| 分块查找 | 块间有序 | 支持 | 顺序 | 中等规模动态表 |
| 二叉排序树 | 自动维护 | 支持 | 链式 | 动态查找 |
| 哈希表 | 无要求 | 支持 | 顺序 | 快速查找，允许冲突 |

## 六、教学重难点

### 6.1 重点内容
- 各种查找算法的基本思想和实现
- 平均查找长度的计算
- 哈希函数的构造和冲突处理
- 二叉排序树的构造和查找
- 不同查找方法的适用场景

### 6.2 难点解析
#### 6.2.1 哈希冲突处理
- 难点：不同冲突处理方法的实现和性能差异
- 解决方法：通过具体例子演示冲突处理过程

#### 6.2.2 平衡二叉树旋转
- 难点：四种旋转类型的判断和实现
- 解决方法：画图分析失衡情况，理解旋转原理

#### 6.2.3 ASL计算
- 难点：不同查找方法ASL的推导
- 解决方法：通过小规模实例手动计算，总结规律

### 6.3 常见错误
- 折半查找中边界条件处理错误
- 哈希函数选择不当导致冲突过多
- 二叉排序树插入时未正确维护树结构
- 平衡二叉树旋转后未更新高度信息

## 七、典型例题

### 7.1 哈希表构造
题目：用除留余数法构造哈希表，处理冲突
解法：选择合适的p值，使用线性探测或链地址法

### 7.2 二叉排序树构造
题目：根据给定序列构造二叉排序树
解法：按顺序插入每个元素，维护BST性质

### 7.3 查找效率分析
题目：比较不同查找方法在特定场景下的效率
解法：根据数据特点和操作需求选择合适方法
